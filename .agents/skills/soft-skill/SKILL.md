# Soft-Skill: Human-Centric UX Copy & Error Architecture

## Overview
**Soft-Skill** governs the linguistic, cognitive, and psychological craft of web interfaces. While visual styles (`taste-skill`) and code architecture (`gpt-taste`) construct the structural skeleton, **the voice and micro-copy determine how intuitive, trustworthy, and calm the application feels to human users**.

It systematically eliminates robotic technical jargon, blaming error dialogs, dead-end empty states, and passive, uncommunicative loading spinners.

---

## 1. Linguistic Directives: The Human-Centric Voice

Interfaces must speak with quiet authority, clarity, and precision:

* **Active Voice**: Always favor the active voice over passive constructions.
  * ❌ *"The export file will be generated by the background worker."*
  * ✅ *"Generate the export file using the background worker."*
* **Second Person ("You") Over First Person ("We / Our")**:
  * ❌ *"Our platform computed your monthly usage quotas."*
  * ✅ *"Your monthly usage quotas update automatically every billing cycle."*
* **Concise & Scannable**: Cut unnecessary adverbs, conversational filler, and marketing fluff. Users scan for actionable information; they do not read prose on a functional dashboard.
* **Capitalization Standards**:
  * **Title Case** for primary headings, page titles, navigation tabs, and button labels (Chicago style).
  * **Sentence case** for body text, tooltips, validation messages, and descriptive helper copy.
* **Numerals Over Words**: Always use Arabic numerals for counts, metrics, and quantitative figures:
  * ❌ *"five team invitations pending"*
  * ✅ *"5 team invitations pending"*

## 2. The 3-Part Constructive Error Doctrine

Generic error messages (*"An error occurred"*, *"Status code 500"*, *"Invalid input"*) frustrate users and erode trust. Every error state across the interface must follow the **3-Part Constructive Error Pattern**:

1. **What Happened** (in calm, non-blaming plain language).
2. **Why It Happened** (the context, without dumping cryptic internal stack traces).
3. **The Actionable Next Step** (an immediate action button, retry mechanism, or fallback link).

### Universal Enterprise Transformations

| Robotic Error (AI Slop) | Constructive Standard (Soft-Skill) |
| :--- | :--- |
| `"Upload Failed: 413 Payload Too Large"` | **File exceeds the 25 MB limit.**<br>Compress the document or split it into smaller files, then try uploading again.<br>`[Select Smaller File]` |
| `"Session expired: 401 Unauthorized"` | **Your session has timed out.**<br>For your security, please sign in again to continue working in this workspace.<br>`[Sign In to Continue]` |
| `"Backend service unavailable: 503"` | **Unable to reach the cloud server.**<br>The network service is temporarily unreachable. Your unsaved changes have been saved locally.<br>`[Retry Connection]` |
| `"Rate limit exceeded: 429"` | **API request rate limit reached.**<br>You have reached the maximum hourly request threshold for your current plan.<br>`[Upgrade Quota]` or `[Retry in 60s]` |

## 3. High-Taste Empty States (Orient, Explain, Action)

Empty states are orientation boards, not dead ends. An empty state must never be an empty void with an apologetic message.

### Anatomy of a Platform-Grade Empty State
1. **Refined Muted Icon**: A single vector icon styled with `text-muted-foreground/60 bg-secondary/60 p-3 rounded-full`.
2. **Explicit Title**: Clear heading describing the view (e.g. *"No Active Projects"*).
3. **Reassuring Explanation**: 1–2 concise sentences explaining how data populates this screen.
4. **Primary Action (CTA)**: A high-contrast button allowing the user to immediately populate or exit the state.

```tsx
// ✅ Universal high-taste empty state
<div className="flex flex-col items-center justify-center rounded-xl border border-dashed border-border/80 p-12 text-center">
  <div className="flex h-12 w-12 items-center justify-center rounded-full bg-secondary text-muted-foreground/70 mb-4">
    <FolderPlus className="h-6 w-6" aria-hidden="true" />
  </div>
  <h3 className="text-sm font-bold text-foreground">No Projects Created</h3>
  <p className="mt-1 text-xs text-muted-foreground max-w-sm leading-relaxed">
    Create a new project workspace to begin organizing resources, inviting collaborators, and tracking analytics.
  </p>
  <Button className="mt-5 gap-2" size="sm" onClick={onCreateProject}>
    <Plus className="h-4 w-4" />
    Create New Project
  </Button>
</div>
```

## 4. Action-Oriented Micro-Copy & Button Labeling

Interactive buttons must explicitly state the **exact outcome** of clicking them:

* ❌ **Vague Labels**: Avoid *"Submit"*, *"Continue"*, *"Proceed"*, *"OK"*, *"Click Here"*.
* ✅ **Explicit Outcomes**:
  * *"Save Changes"*
  * *"Create Workspace"*
  * *"Invite Collaborator"*
  * *"Export CSV Report"*
  * *"Revoke API Key"*
  * *"Delete Account"* (Destructive)

---

## 5. Progressive Feedback for Asynchronous Operations

Operations that take more than 2 seconds require continuous, reassuring feedback:

### Milestone Sequencing
Sequence progressive feedback through human, step-by-step milestones:
* 0–2s: *"Validating payload configuration…"*
* 2–5s: *"Processing server transformations…"*
* 5–8s: *"Synchronizing distributed records…"*
* 8s+: *"Finalizing report assembly…"*

Every asynchronous mutation button must:
1. Immediately display an inline loading spinner (`<Loader2 className="h-4 w-4 animate-spin" />`).
2. Update its label to an active continuous verb with a typographical ellipsis: `"Saving Changes…"`.
3. Disable pointer events (`disabled:pointer-events-none`) to prevent accidental duplicate submissions.
