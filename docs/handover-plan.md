# XSignOn website, Version 2: where we are and what is next

Written for whoever continues the work (ChatGPT, or a person). Read it together with `docs/version-2-plan.md`, `docs/chatgpt-brief.md` and `docs/fidelity-survey.md`.

## 1. The project in four lines

- Public website for XSignOn, a security company: Next.js 16 (App Router), React 19, TypeScript strict, Tailwind v4, Sanity 6 (content), Postgres on Neon (private data), Resend (email), Vercel. Use `npm`, Node 22.
- Repository: https://github.com/xsignon2026/xsignonwebsite. Branch `Version-2` is the working branch (a copy of Jai's `Version-1` plus our fixes). Never push to `Version-1`.
- **The goal of Version 2 is design fidelity:** every page must look and behave exactly like the approved prototype. The prototype is in the repo at `reference/prototype-v5/` (open `index.html#<view>`; view = id without `view-`). It is the "?v=5" (descent) variant of `xsignon-home-beams.html`.
- Compare a page: start the app, then `node scripts/compare-page.mjs <view> <route>` (on Windows Git Bash prefix `MSYS_NO_PATHCONV=1`, and set `APP_URL` if not port 3000). It writes `compare/<view>-<width>-proto.png` and `-app.png` for 1280, 900 and 375.

## 5. Rules for every page

1. Copy the prototype's markup and CSS rules; do not redesign or paraphrase. Same sections, order, words, images, colours, spacing, type sizes, bands and interactions at 1280, 900 and 375 px.
2. Add nothing the prototype does not have: no extra pause buttons, read-time chips, banners or newsletter blocks. (The prototype does have a Pause button on the partner hub and on the About "Why XSignOn" hub: keep those two.)
3. One `h1`, headings in order, labels, keyboard access with visible focus, contrast AA, reduced motion respected.
4. Use `next/image` with width and height. Use `src/lib/link-href.ts` for links from data. No new packages, no `eslint-disable`, no skipped tests.
5. Before every push: `npm run lint`, `npm run typecheck`, `npm run test`, `npx prettier --check .`, `npm run build`, and the page's e2e spec must all pass.
6. Never touch files owned by the other person (`docs/chatgpt-brief.md` lists them). Ask in `docs/v2-requests.md`.

## 6. How work is handed over right now

ChatGPT has no push access from its sandbox, so it delivers each page as a patch file (for example `deliverables/0001-V2-match-PostureOne-to-approved-prototype.patch`). **That PostureOne patch has not reached Claude yet:** the person running this project must save the file onto the local machine (or paste it into the chat) so Claude can review, apply (`git apply --3way` on a `v2/chatgpt-<page>` branch), run all checks and merge it into `Version-2`. Each delivery should come with: the page, the three picture pairs, what is not identical and why, and the check results.

## 7. Things only the project lead can do

- Create the Neon database and give a pooled connection string (`DATABASE_URL`), then run `npm run db:migrate`.
- Create the Resend account, verify the sending domain (SPF, DKIM, DMARC) and provide `RESEND_API_KEY`, `EMAIL_FROM`, `ENQUIRY_INBOX` (a test inbox on staging, the real one on Production only) and `RESEND_WEBHOOK_SECRET`.
- Generate and set `ENQUIRY_HASH_SECRET`, `SIGNED_URL_SECRET`, `UNSUBSCRIBE_SECRET` (each 32+ random characters), `CRON_SECRET`, `ADMIN_USER`, `ADMIN_PASSWORD`. See `.env.example`.
- Sanity: create the project and datasets, set CORS, create the tokens and the publish webhook, send the project ID. Then Claude deploys the schema, imports `data/seed/*.ndjson` and proves publish-to-live.
- Provide real Privacy and Terms text, and confirm the mail DNS records with whoever manages the domain.
